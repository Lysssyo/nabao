# 项目结构与职责

项目有采集器、Java后端、网页管理端和iOS App四个运行部分。当前公开额度只有一个发布出口：采集器生成的每日投票表。后端和两个前端读取同一份结果，不在展示时重新投票，也不人工补值。

## 额度产生与展示

```text
已配置作者的同日数据
    ↓ 每基金、每字段、每作者最多一票
单一有效来源         → 采用该值
多来源唯一最高票     → 采用该值
平票或无有效数据     → 待更新
    ↓
.local/public/YYYY-MM-DD.json + latest.json
    ↓ 后端只读接口
网页管理端 / iOS额度页
```

代码、份额、原表日期和单位的输入检查发生在转录数据进入投票之前。页面只呈现最终投票结果与“待更新”，不把过程检查状态作为额度结论。管理页的“刷新结果”重新读取发布结果；“立即采集”启动当前名单的真实采集，完成后自动读取发布结果。

## Java后端

源码位于 `backend/src/main/java/com/nabao/`。

| 层 | 目录 | 职责 |
| --- | --- | --- |
| HTTP接口 | `web/` | 请求、参数约束、鉴权、HTTP响应及异常映射 |
| 应用业务 | `application/` | 当前表读取、管理摘要匹配、通知订阅与投递编排、事务边界 |
| 应用端口 | `application/port/` | 声明文件仓储、数据库仓储、推送通道所需能力 |
| 领域模型与规则 | `domain/` | 表、状态、通知模型及额度变化、来源共识等规则 |
| 基础设施 | `infrastructure/` | 实际文件读写、数据库SQL、Apple请求与签名、采集控制服务代理 |

接口层调用应用服务，应用服务依赖领域模型与端口，基础设施实现端口；Spring在启动时组装具体实现。应用服务不引用控制器或具体文件/JDBC/APNs实现。主程序保留在根包以扫描各层。

原有数据库接口继续供已有集成调用，当前管理页已不包含任何历史兼容入口，也不请求旧接口。业务主链路不依赖旧观察表。

## 网页管理端

源码位于 `frontend/`，使用 Vue 3、TypeScript 和 Vite。构建产物同步至 `backend/src/main/resources/static/admin/`，由同一个Java服务提供，不需要另起前端生产服务器。

| 模块 | 职责 |
| --- | --- |
| `src/api/` | 同源请求、鉴权、截止时间、错误和取消 |
| `src/domain/` | 类型、数据校验、额度排序与状态文案 |
| `src/composables/` | 内存会话、请求代际、状态轮询与登录图片生命周期 |
| `src/components/` | 连接、额度表、采集任务、作者管理及采集账号组件 |
| `src/pages/` | 页面组合和操作绑定 |
| `src/styles/` | 桌面与移动布局，额度表固定首列、横向滚动 |

管理密钥只留在页面内存中，不写入URL、浏览器存储或数据文件。投票日志通过鉴权接口读取公开笔记链接及字段明细；视图不接触登录会话或模型密钥。

## 采集控制服务

`collector control` 常驻提供任务与登录状态，默认每360分钟检查当前配置的作者。Java通过固定内部地址代理操作，网页不会直接连接采集器。控制服务在本机只监听回环地址；Compose中仅在容器私有网络可达。

手动采集、定时检查与登录共用互斥锁，避免同一账号并行打开会话。登录使用独立临时浏览器，由本人正常扫码；验证登录成功后保存正式会话，取消或超时不替换旧会话。二维码通过鉴权接口返回，Cookie、浏览器配置和模型密钥留在私有数据目录。采集失败或当日没有新表时保留真实已发布日期和数据。站点限制独立显示为“访问受限”，不视为登录失效或扫码就绪；当前进程暂停定时检查，等待本人处理后手动确认。

作者配置保存在采集器私有的 `author-config.json`，首次初始化为原五位作者，支持0～50位。增删和整轮采集共用跨进程租约；一轮使用同一份名单与修订号完成发现、抽取、投票和发布。没有配置作者时禁止采集并暂停定时任务。删除后的作者缓存不参与下一轮投票；已发布历史表保留，直到成功发布新结果。发布水位记录配置修订号，旧名单的迟到任务不能覆盖新名单结果。

## iOS

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 入口与组装 | `ios/App/Entry/` | App生命周期、共享状态组装、通知导航 |
| 功能页面 | `ios/App/Features/Plans/`、`Quotas/`、`Settings/` | 计划、额度和设置的展示与用户交互 |
| 系统与本地服务 | `ios/App/Services/` | 计划存储、截图读取/OCR、备份文件、通知和剪贴板 |
| 共享界面 | `ios/App/Shared/` | 基金选择等复用组件 |
| 核心规则与数据访问 | `ios/NabaoCore/` | 基金目录、表模型、排序与变化规则、备份编解码、HTTP客户端和共享表缓存 |

页面调用服务或核心状态，不直接读写计划文件、请求系统通知权限或执行OCR。基金排序只改变展示顺序，不改公开文件、基金身份或个人计划。

## 投票审计

采集器 `vote-audit.ts` 负责构造每轮作者字段快照及持久化待同步队列；公开额度文件仍是展示的唯一数据源。Java 的 `VoteAuditController → VoteAuditService → VoteAuditRepository → JdbcVoteAuditRepository` 独立处理日志鉴权、校验、幂等、事务和分页。MySQL 的 `vote_audit_batch` 保存批次与作者快照，`vote_audit_entry` 保存每条字段明细。Vue 使用 `VoteAuditPanel` 按需加载批次、筛选博主/字段和分页，不把审计过程放入 iOS 额度表。
