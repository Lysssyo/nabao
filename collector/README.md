# nabao 额度采集器

Node.js 22 / TypeScript。按作者发现近期笔记，完整读取正文和配图，调用 DeepSeek 图片模型转录。当前主流程发布每日 JSON 表，个人定投截图不进入本服务。

## 当前简化版：每日一张表

首次启动默认添加五位作者：美基搭子（`5ddec93c0000000001009aa1`）、老纳（`6168030000000000020278b5`）、纳宝（`64ea885c0000000001004087`）、纳普NaS&P／1572871865（`633116cc000000002303dcaa`）、纳指雷达／94168796616（`6715dd2d000000001d02255b`）。管理端可新增或删除采集作者，之后按保存的列表采集。

固定41份额；费率、代销、直销、跟踪误差、近一年分别按基金和数据日期投票。每作者每字段仅其最新有效同日记录一票；单一有效来源直接采用，多来源按唯一最高票采用，平票或无有效数据待更新。收益须有可核对的截止日，表格更新日不能替代；产品附图净值日期仅作用于对应代码。缺少收益截止日或明确币种/周期的数字保留在日志但不计票，已有完整口径的单一来源仍可采用。已明确的不同截止日、渠道条件和合并额度分别计票。脚注、部分渠道及合并额度不当作普通独立限额。公开文件不含票数或分析过程。每轮字段明细通过持久化待同步队列写入后端投票日志表，失败后在启动和后续处理时补交。

同帖订正、删行与撤回会撤销对应旧票；私有来源状态在 `NABAO_DATA_DIR/table-state`（可用 `NABAO_TABLE_STATE_DIR` 指定）。发布水位含真实更新时间、内容版本、抓取时序和作者配置版本，旧任务不能覆盖新配置或同日新结果。所有当前作者同等计票。

```sh
npm run build
node dist/src/cli.js table --max-notes 6
# 低频常驻；会话有效、运行环境持续在线时，每6小时检查一次。
node dist/src/cli.js table-watch --interval-minutes 360
# 从完整采集证据续跑，无须重新访问小红书。
node dist/src/cli.js table --report /绝对路径/report.json
# 重放已核验的历史表日期；仅适用于单轮 table --report。
node dist/src/cli.js table --report /绝对路径/report.json --date 2026-10-23
```

`NABAO_TABLE_DIRECTORY` 默认 `../.local/public`，输出 `YYYY-MM-DD.json` 和 `latest.json`。每次完整验证后原子替换，缺行、坏响应、未来生效额度和旧日期不能覆盖当前文件。`NABAO_TABLE_CACHE_DIR` 默认数据目录下 `table-cache/`，按来源内容、提示词、模型和目录版本缓存；跨轮复用前仍验证本次原图完整性。

输出只有代码、名称、费率、代销、直销、跟踪误差、近一年，以及表日期、来源和必要业务脚注。完整年份优先取原表，也接受完整日期后的有效时分秒；只有月日时须与已核验的上海发布时间同月日，绝不用采集日期补成今天。隔日发布前日表时，可以重放前日表日期；最终按图表日期计票，不按发帖日改写图表日期。`10→5` 取已生效的新值，未来生效变动不提前发布。平票或无有效数据的字段用待更新/null，不拿昨天的值补成今天。

主页按纳指额度主题区分非置顶与置顶卡片，详情日期再次排序。扫描是有界近期检查，不能声称遍历作者全部历史。`table` 调用 capture-only 采集，不调用旧数据库提交或任务写入接口；iOS 不读取 `daily-table-report.json` 或模型缓存。整表无可采纳字段时保留有效文件，报告受限/失败/无新帖，不冒充已更新。

`table-watch` 单轮异常后仍按正常间隔继续，私有 `data/table-watch/status.json` 记录 lastAttempt、lastSuccess、dataDate、status、errorCode；stderr输出安全状态提醒。部分字段发布可更新lastSuccess，但仍保持partial/受限状态。SIGINT等待当前轮收尾，不中断正在原子发布的文件。状态不推给iOS，也不会主动发送外部消息。

`table` 单轮和 `table-watch` 还写入独立管理摘要：`NABAO_STATUS_FILE`，默认在公开输出目录的同级 `status/daily-table.json`。它只包含检查日期/时间、最后成功时间、固定状态/错误码、本轮作者昵称与状态，以及当前公开表的日期、更新时间、SHA256、采用/待更新字段数；不包含原文、笔记ID、私有路径、模型输出、会话或签名链接。摘要以0644权限原子替换，供不同UID的后端只读；私有状态仍为0600。摘要写入失败只报告 `STATE_WRITE_FAILED`，不撤销已经完成的发布或终止下一轮。

管理摘要将 `attemptedDate` 与 `published.dataDate` 分开：例如10/24未发现新表时，当前10/23表的采用/待更新数仍按10/23实际文件计算，不被本轮0行覆盖。三个非null指标与两个非“待更新”额度分别计为已采用，含明确限定条件的值；它描述公开展示内容，不暴露投票过程。后端将摘要和公开文件的摘要/日期/统计核对，版本不一致时只展示实际表并标明状态未知。默认超过12小时未检查显示陈旧；失败检查不刷新最后成功时间。

### 采集完整性与恢复

- 结构化图片清单缺少某张 URL 时，可用同页明确序号的已加载图片补齐；作者、正文和总图数必须一致，不能凭排列顺序猜图。已有 HTTPS 原图地址优先于 HTTP 地址。
- 页面状态仅安全解析已观察到的空 Map 字面量，不执行 JavaScript 表达式。优先使用身份匹配的真实笔记时间与图片清单；页面状态存在但无法解析时，不回退到实测为渲染时间的 JSON-LD 日期。
- 已参与投票的笔记修改标题或正文后，即使不再出现额度关键词，也继续核对完整配图。删除字段、删行以重新抽取的内容为准，不把改标题直接当成撤回。
- 无效模型响应、零有效行和全未知结果不作为可复用抽取缓存；旧坏缓存与旧来源状态会重新尝试抽取。有效局部结果和明确撤回仍可复用，修改时间也参与缓存键。
- 来源状态保留真实完整/部分核验结果，复用时不会把已完整来源降为部分；旧缓存未记录该结果时保持保守，不能仅凭41行声称完整。
- 可信目录和作者精确别名的摘要参与来源状态验证版本；更新名称核验规则后重验已缓存的原始转录，避免旧的部分行结果永久阻止恢复。
- 单篇抽取的意外异常记录安全错误码，继续处理其他作者。来源发现或抓取不完整时，复用旧表也会报告失败/受限，不将其记为成功检查。日志/告警回调异常不终止常驻采集。
- `table` 和 `table --report` 使用同一个数据目录下的 `table-state/`；重放证据时需保持 `NABAO_DATA_DIR` 或 `NABAO_TABLE_STATE_DIR` 一致。未配置环境变量时 CLI 使用 `collector/data/table-state/`。

`scan.lock`、`.daily-table-run.lock` 和 `.daily-table.lock` 是私有锁目录。每个锁还有短期的同名`.guard`目录，将创建、失效恢复及释放串行化，防止旧一代按路径删除新一代目录。进程若在该临界区被强杀，遗留guard不会猜测删除；先确认没有采集进程，再人工检查原锁与同级guard。仅删除原锁目录不能解除遗留guard。只在能确认同一机器启动会话及 PID 命名空间内的持有进程已经退出时自动恢复；活跃进程的锁不会被抢占。旧格式、空目录、损坏或跨机器/容器命名空间的锁保守返回 `SCAN_BUSY`、`TABLE_RUN_BUSY` 或 `TABLE_PUBLICATION_BUSY`，需先确认没有采集/发布进程再人工清理。此机制不保证自动恢复所有宿主机重启或锁初始化期间的中断。

## 本地启动

```sh
cd collector
npm ci
cp .env.example .env
npm run browsers:install
npm test
npm run doctor
```

填写 `.env` 的模型密钥和后端内部密钥。CLI 自动读取当前目录的 `.env`，已有进程环境变量优先。`doctor` 只检查配置，不访问模型或小红书。

如需要登录，在独立会话中完成一次正常登录：

```sh
npm run build
node dist/src/cli.js login
node dist/src/cli.js scan --max-notes 1 --headed
```

`NABAO_BROWSER_PROFILE` 只能指向项目自己的私有目录，不要填日常浏览器配置目录。`NABAO_BROWSER_CHANNEL=chrome` 使用已安装的 Chrome；不设置则使用 Playwright Chromium。本机已验证登录后的无头模式；服务器访问仍需在目标环境验证。没有专用会话配置时使用独立匿名上下文。

## 管理端采集与扫码登录

日常运行使用 `node dist/src/cli.js control`。它是独立常驻服务，启动后不会立即访问小红书；默认每360分钟采集当前列表中的作者。管理端“立即采集”复用同一个 `runTableWatch → updateDailyTable → voteDailyTables` 流程，不只是重新读取JSON。无当日新表时保留现有数据和原数据日期。浏览器刷新或断开不停止后台任务；重启后未完成任务标记为中断。

管理端“采集作者”可填写昵称和完整作者主页链接后新增，也可删除已有作者。链接格式为 `https://www.xiaohongshu.com/user/profile/24位作者ID`；允许携带分享查询参数，保存时移除参数和片段，不访问或解析短链接。昵称为1～80字，最多50位作者，重复作者返回409。列表可清空；空名单时禁止采集并暂停定时，至少有一位作者后按原定时间隔继续。

作者列表保存在 `NABAO_DATA_DIR/author-config.json`，首次缺失时从源码默认列表初始化，后续不补回删除的作者；空列表和文件损坏不会触发重置。文件权限0600、原子替换，修改增加配置版本。管理端和CLI共享 `.author-config.lock`，一轮采集、抽取、投票和发布使用同一份不可修改的作者快照；期间新增/删除返回409。重放旧报告也使用当前配置，已删除作者的旧缓存不再参与投票。删除操作保留原始证据及当前公开表，新结果在下一次成功形成投票后发布。

Java 后端连接 `NABAO_CONTROL_URL`（默认 `http://127.0.0.1:18082`），使用 `NABAO_CONTROL_KEY`（Java默认 `INTERNAL_API_KEY`）代理。Node对应密钥默认取 `NABAO_INTERNAL_KEY`，必须至少16字符。两端配置应一致；此密钥、模型密钥、cookies和原始页面不返回浏览器。

| 控制配置 | 默认值 |
| --- | --- |
| `NABAO_CONTROL_HOST` | `127.0.0.1`；Compose内为`0.0.0.0`但不映射宿主端口 |
| `NABAO_CONTROL_PORT` | `18082` |
| `NABAO_CONTROL_SCHEDULE_ENABLED` | `true`；`false`只允许手动采集 |
| `NABAO_CONTROL_INTERVAL_MINUTES` | `360`，允许60～10080 |
| `NABAO_CONTROL_HEADLESS` | `true`；采集和会话检查是否使用无界面浏览器 |
| `NABAO_LOGIN_HEADLESS` | 默认继承上项；本地设`false`可显示登录专用 Chrome，采集仍可保持无界面 |

同一时刻只执行采集、登录或会话检查中的一种。控制服务有独立实例锁，登录/会话检查与CLI采集、CLI登录、会话导出共享 `scan.lock`；并发请求返回409。后台任务的开始/结束和安全结果保存于 `control/status.json`，不保存凭据。没有配置专用profile或storage文件时，服务在私有数据目录创建专用profile。

管理端登录先复用项目专用会话，已登录则直接确认，无需重复扫码。需要登录时：点击“登录小红书”→查看二维码→本人用小红书App扫描并确认→点击“已完成登录”。临时profile从项目自己的已保存profile复制身份和站点状态，排除缓存、进程标记和符号链接；外部浏览器占用目录时拒绝复制或替换。只有页面确认`loggedIn=true`、非guest账号、可见的“我”链接匹配该账号后才提交。账号ID兼容`user_id`和`userId`及显式Vue ref；若两字段冲突或任一已提供字段格式错误，拒绝确认登录。profile和导出state一起提交，失败回滚；取消/10分钟超时不会替换正式会话。确认登录只读取当前页面，不刷新用户正在操作的二维码；二维码渲染有有限等待。“检查登录”会实际打开已保存会话，不把文件存在当成登录成功。登录PNG只通过鉴权代理展示，不缓存、不写入公开目录。

出现300012、安全限制或IP风险页面时，登录/会话状态明确返回`restricted`，不会显示二维码已就绪或把会话标为过期。浏览器立即关闭，正式会话保持不变；失败页PNG只暂存在服务内存，通过鉴权入口读取。该进程暂停自动采集，直到用户手动检查登录或完成登录、确认平台恢复可访问后再恢复原定时配置。安全状态文件仅额外保存访问受限标记；服务重启后继续暂停，直到用户明确检查成功或完成登录。未受限会话仍在重启后回到未检查。只有页面实际渲染二维码时才显示扫码等待。

若小红书要求滑块或其他需要鼠标操作的安全验证，必须由本人在同一运行环境处理；本地可设`NABAO_LOGIN_HEADLESS=false`显示正常登录窗口，服务器可使用受保护的远程桌面。访问受限会停止本次登录；恢复后需确认登录成功才恢复定时采集，单纯看到登录页不会解除暂停。可见窗口未识别到二维码时返回`waiting_browser`，保留窗口与当前页面预览供本人按正常入口登录；管理端明确区分页面预览和二维码，确认、取消与10分钟超时仍适用。无界面模式未找到二维码则结束本次登录。二维码面板仅展示普通登录页，不代解验证码，也不保证服务器网络能通过平台风控。不要向管理端或聊天粘贴cookies/模型密钥。

排查页面结构变动时可临时设置`NABAO_LOGIN_DIAGNOSTICS=true`。日志仅包含固定字段的类型、ref标记、布尔校验和匹配数量，并在单个浏览器内去重；不含账号ID、页面文本、URL或会话。默认关闭，排查完成后移除此配置。

Node内部固定接口为`GET /status`、`POST /runs`、`POST /login`、`POST /login/complete`、`DELETE /login`、`GET /login/preview`、`POST /session/check`，以及`POST /authors`（JSON `{name,profileUrl}`）和`DELETE /authors/{id}`；作者操作返回完整控制状态。全部要求`X-Internal-Key`，返回`no-store`，仅作者入口接受校验后的主页链接，不允许指定命令或文件路径。浏览器只访问Java的`/internal/v1/collector`系列接口，不能直接访问内部控制端口。

## 常用命令

以下 `scan/process/submit/watch` 为保留的旧观察发布流程；每日文件表使用上面的 `table/table-watch`。

- `scan --max-notes 6`：每个作者检查最近 6 篇，可设 1～20；既找新笔记，也检测编辑。
- `scan --source 作者ID`：仅检查一位作者。
- `scan --known-notes`：仅复查用户提供的已知分享笔记，用于诊断，不算自动追新验证。
- `process --capture /绝对路径/capture.json`：从完整证据续跑模型、校验和发布，无需重新抓取。
- `watch --interval-minutes 360`：低频常驻扫描；最短 60 分钟。受限时不快速重试。部署前先在该环境跑通单轮。
- `submit --file 批次.json`：旧的内部观察接口诊断入口，不是日常人工工作流。

退出码：0 完成，1 本地运行错误，2 部分完成，3 发现或访问受阻。整轮成功要求所有已发现笔记处理完成；抓到原文不等于已发布额度。

## 正确性边界

- 普通 HTTP 优先，内容不足时正常渲染；只接受确切作者/笔记、明确发布时间和完整图片，HTTP 200 登录页不算成功。
- 只使用页面实际提供的访问链接。主页卡片同时存在裸链接与带访问参数的链接时保留后者。
- 图片需通过 HTTPS、格式、大小和摘要检查。正文和图片指纹共同决定版本；模型只接收这些公开证据。
- 模型只转录候选字段，不能提供作者、发布时间等来源身份，也不能凭知识补造代码。
- 基金名称和明确代码通过天天基金基金清单交叉核对；区分份额、人民币/美元及现钞/现汇。无法唯一匹配则保留异常。
- 代销汇总不等于已验证支付宝限额；申购不等于已有定投；数据每天更新不等于每日累计额度。缺少依据时保留未知。
- 缺图、请求失败和截断结果不发布。完整响应中的可核对行可以发布，不确定基金或同范围矛盾行排除并保持 partial 报告；全不可解析不能清空旧数据，明确成功的空表才可清空。
- 后端发布使用完整笔记快照，支持修改后删行、旧版本防复活和幂等。抽取缓存与内容版本、模型、提示词版本绑定；发布失败可重试而不用重复调用模型。
- 402 余额不足、验证码、登录墙和访问限制均明确报告，不自动绕过或当成无更新。

## 数据与管理页

私有数据目录由 `NABAO_DATA_DIR` 指定，包含 `state.json`、基金清单缓存及 `runs/<run-id>/`。

每篇笔记保留 HTML、全部图片、`capture.json`、`extraction.json`、`normalized.json`、`processing.json` 和实际发生的 `submission.json`。原始证据不进 Git。旧scan流程的报告上传仅包含笔记 ID、状态和错误码等摘要；每日表流程不依赖旧报告数据库。后端Vue管理端 `/admin/` 通过鉴权接口 `/internal/v1/table-status` 展示当前额度投票结果与本轮作者提供的投票数据；已删除历史兼容页面。展示值来自投票，未达到投票规则的字段统一显示“待更新”；采集失败单独提示，不将转录过程状态作为额度结论。

`scan.lock` 防止同目录并发，异常退出后的恢复边界见上文。账号会话单独保存在专用目录，不随报告上传。

## Docker 与验证

镜像默认运行 `doctor` 作为独立诊断。根目录 Compose 默认启动常驻 `control`，每6小时检查且允许管理端手动采集、扫码登录；不再需要tools profile。不要另外启动table-watch重复调度。同机私有控制端口不公开到宿主机。

Compose 将公开文件放在 `public-data`，安全管理摘要放在独立 `status-data`；后端仅只读挂载这两个卷，不能读取 `collector-data` 的原文、会话或私有报告。`/app/status` 由collector UID1000写入。自定义绑定目录也须让collector可写、后端可读摘要；不通过放开整个私有数据目录解决权限问题。后端 `/api/v1/readiness` 检查公开表可读性，`/api/v1/health` 保留原有服务/推送状态口径。

无桌面服务器优先使用上面的管理端二维码登录。以下仍可作为人工迁移已授权专用会话的方式；迁移前停止控制服务，再在本地专用登录会话导出私有会话文件：

```sh
NABAO_BROWSER_STORAGE_STATE=../.local/xhs-session.json node dist/src/cli.js session-export
```

文件权限为 0600，和其他凭据一样不得提交或分享。将该项目专用会话文件单独复制或挂载到目标运行环境的私有数据卷，保证容器 `node` 用户可读且权限为 0600；不要把它 COPY 进镜像。设置 `NABAO_BROWSER_STORAGE_STATE=/app/data/xhs-session.json`；容器使用自带 Chromium，不需要 `NABAO_BROWSER_PROFILE` 或日常 Chrome。会话过期时重新正常登录并更新文件，采集器会报告失败。本机已验证新 Chromium 上下文加载该文件后自动完成两作者采集；服务器的网络和会话有效性仍需实际验证。

`npm test` 包含解析、图片完整性、原文版本、模型请求/响应、基金身份、失败重试及自动快照发布测试；使用本地 HTTP 测试服务和合成 fixture，不读 `.env` 或调用外网。

### 计票口径与证据复用

完全同义且无附加条件的“暂停”“暂停申购”“暂停购买”“停止申购”“停购”统一为“暂停申购”；“无代销”“暂停大额申购”“暂停赎回”和部分渠道条件仍分开。数字额度须有明确币种、周期；近一年收益须有明确收益/净值截止日，缺少这些口径的原值保留日志并标明未计票原因，不作为反对完整口径数据的一票。

v6转录提示要求逐基金记录产品附图的净值日期，不能把表格更新日或其他代码的日期套给整表。验证指纹包含提示版本，必要时重新转录；相同笔记版本、图片SHA、表日期与字段原值下，已验证的单位证据不会被一次转录遗漏抹除。笔记、图片、金额、日期或代码变化时不复用；新证据优先，撤回字段不复用。
