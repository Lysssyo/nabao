# nabao

用于记录跨渠道基金定投、查看公开额度变化并前往渠道处理的 iOS 工具。

个人计划留在手机本地。后端处理公开额度信息和匿名通知订阅；采集器负责追踪指定的小红书作者。没有用户账号或个人计划云同步。

当前简化版由美基搭子、老纳、纳宝、纳普NaS&P（1572871865）、纳指雷达（94168796616）按基金、日期、字段分别投票。每作者每字段最多一票，唯一最高且至少两票采用，平票/单源显示待更新。采集器输出日期 JSON 和 `latest.json`，额度数据不写数据库；后端只读文件，iOS 只展示最终表格。范围固定为41个纳指100份额。

## 当前进展

| 组件 | 已实现 | 尚待接通或验证 |
| --- | --- | --- |
| iOS | 固定基金列、搜索、全部/有额度/我的定投筛选、确认额度变化标记、本地缓存、计划与截图导入 | Apple 签名与真实 APNs 投递、真机回归 |
| 后端 | 文件表只读、仅确认额度变化推送、未知值保留比对基线、匿名登记/退订与持久重试 | Apple 凭据配置与实际投递 |
| 采集器 | 五位作者10/21真实采集、逐字段投票、同日订正防回退、文件发布、失败后继续低频运行及私有状态记录 | 服务器环境与多日稳定性 |
| 工程 | 后端与 Swift 测试、模拟器构建、本地推送全链路脚本、源码镜像与 MySQL/Chromium 验收、CI/CD 配置 | 远程工作流执行、部署服务器 |

模型由采集器配置和调用。采集、抽取、归一化、发布各自保留状态；未通过的真实额度不会写成可用结果。

10/21五源实际结果：205个字段中97个采用、108个待更新；33个份额至少一个渠道有确认额度或暂停状态，15个份额有明确正数额度。跟踪误差和近一年未达到两份同口径来源支持，保留待更新。文件、HTTP接口与模拟器缓存逐字段一致，详见验证记录。

## 目录

- `ios/`：SwiftUI 客户端、截图识别和本地计划。
- `backend/`：每日表只读 API 和匿名通知；旧观察接口保留兼容。
- `collector/`：作者发现、正文/配图采集及模型接入。
- `docs/contract.md`：第一版边界与组件接口。
- `.local/`：本地测试输入和运行证据，不进入 Git。
